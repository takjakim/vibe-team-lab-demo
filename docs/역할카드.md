# 역할 카드

팀원 다섯 명이 역할 A부터 E까지 하나씩 맡는다. 네 명 팀이면 역할 E(공지)를 강사가 맡는다. 각 역할은 자기 파일만 수정하므로 PR끼리 충돌하지 않는다.

모든 역할에 공통으로 적용되는 규칙은 다음과 같다.

- 섹션 파일은 `meta`와 `render(root, data)`를 내보낸다. `meta`의 id는 바꾸지 않는다.
- 요소는 `src/lib/dom.js`의 `el()`로 만들고, 스타일은 `src/styles/base.css`의 공용 클래스를 쓴다.
- 작업이 끝나면 `node scripts/check.mjs`와 로컬 서버(`python3 -m http.server 8000`)로 확인한다.
- 이슈 번호는 시드 스크립트로 처음 만든 저장소 기준이다. 팀 저장소의 실제 번호를 확인한다.

| 역할 | 섹션 | 담당 파일 | 데이터 | 이슈 |
|---|---|---|---|---|
| A | 팀 소개 | `src/sections/about.js` | `src/data/team.json` | #1 |
| B | 할 일 보드 | `src/sections/board.js` | localStorage | #2 |
| C | 주간 일정 | `src/sections/schedule.js` | `src/data/schedule.json` | #3 |
| D | 테마 | `src/sections/theme.js`, `src/styles/theme.css` | 테마 훅 | #4 |
| E | 공지 | `src/sections/notice.js` | `src/data/notices.json` | #5 |

---

## 역할 A: 팀 소개

- **담당 섹션**: 팀 소개(`#about`)
- **담당 파일**: `src/sections/about.js`
- **data**: `team.json` 배열. 항목은 `{ name, role, focus, github }`
- **쓸 클래스**: `.grid`, `.profile`, `.badge`, `.empty`

**완료 기준**

- team.json의 모든 항목이 카드 하나씩으로 표시된다.
- 카드마다 이름, 역할, 관심 분야, GitHub 프로필 링크가 있다.
- 폭 390px 화면에서도 카드가 잘리지 않는다.
- 항목이 0개이면 "아직 등록된 팀원이 없습니다."를 보여 준다.

**에이전트 프롬프트 예시**

```text
이슈 #1을 구현해 주세요. src/sections/about.js만 수정합니다.
render(root, data)에서 data(team.json 배열)의 각 항목을 ../lib/dom.js의 el()로 .profile 카드로 만들고 .grid 요소 안에 넣어 주세요.
카드에는 이름(h3), 역할(.badge), 관심 분야, https://github.com/아이디 링크를 넣고 링크는 새 탭으로 엽니다.
항목이 없으면 .empty 문단에 "아직 등록된 팀원이 없습니다."를 보여 주세요. innerHTML은 쓰지 않습니다.
끝나면 node scripts/check.mjs를 실행해 통과를 확인해 주세요.
```

## 역할 B: 할 일 보드

- **담당 섹션**: 할 일 보드(`#board`)
- **담당 파일**: `src/sections/board.js`
- **data**: 없음. 할 일은 localStorage의 `vibe-team-lab:board` 키에 저장한다(`STORAGE_KEY` 상수).
- **쓸 클래스**: `.field-row`, `.input`, `.btn`, `.btn-danger`, `.btn-sm`, `.list`, `.list-item`, `.grow`, `.is-done`, `.muted`

**완료 기준**

- 입력 후 추가 버튼 또는 Enter로 할 일이 추가된다. 빈 값은 추가되지 않는다.
- 항목마다 완료 체크박스와 삭제 버튼이 있고, 완료 항목은 취소선으로 보인다.
- 새로고침 후에도 목록이 유지된다.
- 남은 할 일 개수를 보여 준다.
- 저장값이 깨져 있어도 오류 없이 빈 목록으로 시작한다.

**에이전트 프롬프트 예시**

```text
이슈 #2를 구현해 주세요. src/sections/board.js만 수정합니다.
form(.field-row) 안에 input(.input)과 추가 버튼(.btn)을 두고, submit 이벤트로 할 일을 추가합니다. 빈 문자열은 무시합니다.
목록은 ul.list와 li.list-item으로 그리고, 각 항목에 체크박스, 내용(span.grow), 삭제 버튼(.btn .btn-danger .btn-sm)을 둡니다. 완료 항목의 li에는 .is-done을 붙입니다.
상태는 [{ id, text, done }] 배열로 localStorage의 STORAGE_KEY에 JSON으로 저장하고, 읽을 때 JSON.parse가 실패하면 빈 배열로 시작합니다.
목록 아래에 "남은 할 일 N개"를 .muted로 보여 주세요. 끝나면 node scripts/check.mjs를 실행해 주세요.
```

## 역할 C: 주간 일정

- **담당 섹션**: 주간 일정(`#schedule`)
- **담당 파일**: `src/sections/schedule.js`
- **data**: `schedule.json` 객체 `{ week, items: [{ day, time, title, owner }] }`. day는 "월"부터 "금"까지다.
- **쓸 클래스**: `.day-group`, `.is-today`, `.list`, `.list-item`, `.grow`, `.badge`, `.muted`

**완료 기준**

- 월요일부터 금요일 순서로 요일 묶음을 만들고, 묶음 안은 시간순으로 정렬한다.
- 항목마다 시간, 제목, 담당자를 보여 준다.
- 오늘 요일 묶음을 강조한다.
- 일정이 없는 요일은 "일정 없음"으로 표시한다.

**에이전트 프롬프트 예시**

```text
이슈 #3을 구현해 주세요. src/sections/schedule.js만 수정합니다.
data.items를 ["월","화","수","목","금"] 순서의 요일별 묶음(div.day-group, 제목 h3)으로 나누고, 각 묶음 안은 time 문자열 기준 오름차순으로 정렬해 ul.list에 li.list-item으로 그려 주세요.
항목에는 시간(strong), 제목(span.grow), 담당자(.badge)를 넣습니다. 일정이 없는 요일에는 "일정 없음"을 .muted로 보여 줍니다.
new Date().getDay()로 오늘 요일을 구해 해당 묶음에 .is-today를 붙이고, 맨 위에 data.week를 .muted 문단으로 보여 주세요.
끝나면 node scripts/check.mjs를 실행해 주세요.
```

## 역할 D: 테마

- **담당 섹션**: 테마(`#theme`)와 사이트 전체 다크 모드
- **담당 파일**: `src/styles/theme.css`, `src/sections/theme.js`
- **data**: app.js가 넘겨 주는 테마 훅
  - `getPreference()`: 저장된 선호값 `'system' | 'light' | 'dark'`
  - `getCurrent()`: 지금 적용된 값 `'light' | 'dark'`
  - `set(값)`, `toggle()`, `onChange(fn)`
- **쓸 클래스**: `.choice-group`, `.visually-hidden`, `.muted`, `.theme-toggle`(헤더 버튼)

**완료 기준**

- theme.css의 `:root[data-theme="dark"]`에 `color-scheme: dark`와 base.css의 모든 색 변수 다크 값을 정의한다.
- 헤더 버튼으로 다크 모드를 켜면 화면 전체 색이 바뀌고 새로고침 후에도 유지된다.
- 테마 섹션에서 "시스템 설정 따르기", "라이트", "다크"를 고를 수 있다.
- 헤더 버튼으로 바꿔도 테마 섹션의 선택 상태가 함께 바뀐다.

**에이전트 프롬프트 예시**

```text
이슈 #4를 구현해 주세요. src/styles/theme.css와 src/sections/theme.js만 수정합니다.
theme.css: :root[data-theme="dark"] 안에 color-scheme: dark와 base.css :root에 있는 --color-로 시작하는 변수 전부의 다크 값을 정의해 주세요. 본문 글자 대비는 4.5:1 이상이 되게 합니다.
theme.js: data는 테마 훅입니다. fieldset.choice-group 안에 라디오 버튼 3개(system: 시스템 설정 따르기, light: 라이트, dark: 다크)를 그리고, 처음 선택값은 data.getPreference()로 정합니다. 선택이 바뀌면 data.set(값)을 부릅니다.
data.onChange로 헤더 버튼에 의한 변경도 받아 라디오 선택과 "현재 적용: 라이트/다크" 문구를 갱신해 주세요.
끝나면 node scripts/check.mjs를 실행해 주세요.
```

## 역할 E: 공지

- **담당 섹션**: 공지(`#notice`)
- **담당 파일**: `src/sections/notice.js`
- **data**: `notices.json` 배열. 항목은 `{ id, date, level, title, body }`이고 level은 `info` 또는 `important`다.
- **저장**: 닫은 공지 id 목록은 localStorage의 `vibe-team-lab:dismissed-notices` 키(`STORAGE_KEY` 상수)
- **쓸 클래스**: `.banner`, `.is-important`, `.banner-title`, `.grow`, `.btn-ghost`, `.btn-sm`, `.empty`

**완료 기준**

- 공지를 날짜 최신순으로 배너로 보여 주고, important 공지는 강조한다.
- 닫기를 누른 공지는 새로고침 후에도 다시 나오지 않는다.
- 모두 닫으면 "새 공지가 없습니다."와 "닫은 공지 다시 보기" 버튼을 보여 준다.
- 닫기 버튼에 접근성 이름(`aria-label`)이 있다.

**에이전트 프롬프트 예시**

```text
이슈 #5를 구현해 주세요. src/sections/notice.js만 수정합니다.
data(notices.json 배열)를 date 내림차순으로 정렬하고, localStorage의 STORAGE_KEY에 저장된 닫은 id 배열에 없는 공지만 div.banner로 그려 주세요. level이 "important"이면 .is-important를 붙입니다.
배너 안에는 div.grow(제목 p.banner-title, 날짜와 본문 p)와 닫기 버튼(.btn .btn-ghost .btn-sm, aria-label="공지 닫기")을 둡니다. 닫기를 누르면 id를 저장하고 다시 그립니다.
남은 공지가 없으면 .empty로 "새 공지가 없습니다."와 "닫은 공지 다시 보기" 버튼을 보여 주고, 버튼을 누르면 저장값을 지우고 다시 그립니다.
localStorage 읽기가 실패해도 오류 없이 동작하게 해 주세요. 끝나면 node scripts/check.mjs를 실행해 주세요.
```
