# 팀 운영 규칙

다섯 명이 같은 저장소에서 에이전트와 함께 일할 때 지키는 규칙이다. 규칙의 목적은 서로의 작업이 부딪히지 않게 하고, 무엇을 누가 왜 바꾸었는지 기록으로 남기는 것이다.

## 1. 브랜치 이름

형식은 `<종류>/<이슈번호>-<짧은설명>`이다. 짧은설명은 영어 소문자와 하이픈으로 쓴다.

| 종류 | 용도 | 예 |
|---|---|---|
| `feat/` | 기능 추가 | `feat/2-todo-board` |
| `fix/` | 버그 수정 | `fix/9-notice-close` |
| `docs/` | 문서만 수정 | `docs/12-guide-typo` |
| `drill/` | 강사용 드릴 브랜치 | `drill/instructor-card-20261016` |

- 이슈 하나에 브랜치 하나를 만든다. Orca에서 워크트리를 만들 때 이 이름을 그대로 쓴다.
- 병합된 브랜치는 자동으로 삭제된다(저장소 설정).

## 2. 커밋 메시지

형식은 Conventional Commits의 `type: 요약`이다. 요약은 한국어로 쓸 수 있으며 50자 안팎으로 끝을 맺는다.

| type | 쓰는 경우 |
|---|---|
| `feat` | 사용자에게 보이는 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 변경 |
| `style` | 동작과 무관한 서식, CSS 정리 |
| `refactor` | 동작을 바꾸지 않는 코드 구조 변경 |
| `test` | 검사나 테스트 추가 |
| `chore` | 설정, 스크립트 등 그 밖의 작업 |

예시는 다음과 같다.

```text
feat: 할 일 보드에 추가와 삭제 기능 구현
fix: 공지 닫기 상태가 새로고침 후 사라지는 문제 수정
style: 다크 모드 배경 대비 조정
```

에이전트가 커밋 메시지를 생성하더라도 이 형식에 맞는지 확인하고 필요하면 고친다.

## 3. PR 크기와 본문

- PR 하나에는 파일 3개, 변경 300줄 이내를 권장한다. 넘으면 이슈를 나누어 PR을 여러 개로 만든다.
- 본문은 PR 템플릿을 따른다. 변경 요약, 관련 이슈, 확인 사항, 스크린샷을 채운다.
- 관련 이슈는 `Closes #이슈번호`로 적어 병합 시 이슈가 자동으로 닫히게 한다. 여러 사람이 같은 이슈로 PR을 올리는 충돌 드릴에서는 `Refs #이슈번호`를 쓴다.
- 병합 방식은 Squash and merge 하나만 쓴다. 이슈 하나가 main에 커밋 하나로 남는다.

## 4. 리뷰

| 항목 | 기준 |
|---|---|
| 승인 수 | 1명 이상(main 보호 규칙) |
| 첫 응답 시간 | 실습 중에는 리뷰 요청 후 10분 이내, 실제 프로젝트에서는 1 영업일 이내 |
| 상태 검사 | CI의 `check`가 통과해야 병합할 수 있다 |
| 병합 담당 | PR 작성자가 승인을 받은 뒤 직접 병합한다 |

리뷰어는 다음을 확인한다.

1. 이슈의 완료 기준을 모두 만족하는가.
2. 담당 파일만 바뀌었는가. 공용 파일이 바뀌었다면 변경을 요청한다.
3. 화면 문구가 한국어이고, 데이터를 innerHTML에 넣지 않았는가.
4. 로컬에서 `gh pr checkout <번호>` 후 화면을 직접 확인했는가.

의견은 "무엇이 문제인지"와 "어떻게 바꾸면 좋은지"를 함께 적는다. 단순 제안은 "제안:"으로 시작해 필수 수정과 구분한다.

## 5. 에이전트 사용 표기

- PR 본문에 `에이전트: <도구 이름>` 줄을 반드시 남긴다. 예: `에이전트: Claude Code`, `에이전트: Codex`, `에이전트: 직접 작성`.
- 에이전트에게 준 핵심 프롬프트를 한 줄로 덧붙이면 리뷰어가 의도를 파악하기 쉽다.
- 에이전트가 만든 코드도 작성자가 책임진다. 커밋 전에 디프를 직접 읽고 `node scripts/check.mjs`를 실행한다.

## 6. 금지 사항

| 금지 | 이유 | 대신 할 일 |
|---|---|---|
| main 직접 푸시 | 리뷰와 검사를 건너뛴다 | 브랜치와 PR로 반영한다 |
| 공용 파일 임의 수정(`index.html`, `src/app.js`, `src/sections/index.js`, `src/lib/dom.js`, `src/styles/base.css`) | 다섯 명 모두의 PR과 충돌한다 | 필요한 변경을 이슈로 제안한다 |
| 다른 역할의 섹션 파일 수정 | 담당자의 작업과 충돌한다 | 담당자에게 리뷰 의견으로 전달한다 |
| 비밀값 커밋(API 키, 토큰, 비밀번호) | 공개 저장소에 영구히 남는다 | `.env.local`에 두고 커밋하지 않는다 |
| 남의 브랜치 강제 푸시 | 다른 사람의 작업을 지운다 | 자기 브랜치에서만 `--force-with-lease`를 쓴다 |

비밀값을 실수로 커밋했다면 즉시 강사에게 알리고 해당 키를 폐기한다. 커밋을 지워도 이미 공개된 값은 안전하지 않다.
